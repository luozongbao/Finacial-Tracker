Three short steps. You will need the database and mail details from whoever runs your server.

Database connection

Implementation note

There is no database host field. The host is DB_HOST in config.template.php and is not part of the installer's seven collected values.

The stepper is a status list, not a navigation menu. Its items are not links and cannot be clicked — a visitor cannot reach step 3 without passing through step 2.

Step 1 — connection refused

Database connection

The database server refused the connection.

Check that the database server is running and that the host and port are correct.

Step 1 — unknown database

Database connection

There is no database with that name.

Create the database first, or correct the name.

Step 1 — permission denied

Database connection

The database user was denied access.

Check the user's permissions, and that it may use this database.

Security rule

The three connection failures are described in plain language. The raw driver error — with its SQL state, its errno and its message — is never shown on the page. It goes to the server log.

Mail server

Mail is only needed for password reset links. You can skip this step and add it later.

Implementation note

Both actions are offered: test the connection and continue, or skip and continue. Skipping is a legitimate choice, not a failure — the password reset page tells the visitor that mail is not configured.

Step 2 — the mail details are half filled in

Mail server

If you set an SMTP host, the user and password are required too.
Rule

The mail step is all-or-nothing: a host without a user and a password is a half-configuration, and the server says so rather than silently writing a broken config.

Implementation note

The summary is rendered by the server from the values it collected. The passwords are shown as a mask — the real value is never echoed into the page.

The switch writes ALLOW_REGISTRATION as a real boolean — true or false, never the strings "true" or "false". A string "false" would compare unequal to false and leave registration open.

Implementation note

The "Delete install.php now." block is the most prominent thing on the page — it is the last security step of the installation, and a live installer is a re-configuration hole.

The page has no application navigation and no footer link farm. The installer is not part of the product; it is a setup tool.
