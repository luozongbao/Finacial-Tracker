Financial Tracker — design system

The reference page for every mockup in this folder. Every colour, size, radius and component below comes from a token in assets/tokens.css — the same file the application will reuse verbatim.

Specification

This page implements docs/issues/issue-004.md. It is the single source of truth for the appearance of the application: a mockup that invents a colour, a size or a button style is a defect.

1. Decisions

issue-004 §5 lists three questions the design must settle. Here are the answers, and every screen in this folder follows them.

The three navigation and layout decisions
Question Decision Why
Transaction form: page or modal? A page. Simpler to render and validate in PHP, works without JavaScript, and keeps the browser's back button meaningful. 07-transaction-form.html is a page.
Primary navigation Top bar on desktop; bottom bar under 640 px. A top bar suits a four-item desktop layout; a bottom bar keeps the four destinations within thumb reach on a phone and guarantees 44 px touch targets.
Does the dashboard replace the transaction list? It embeds a short recent list. The dashboard answers "how is this period going?" without a second click, but the full ledger stays one link away. The recent list uses the same row component as the full list.
Decision — surface tokens

issue-004 §6.1 asks whether the application adopts the proposed --surface / --surface-2 extension. It does. The neutral ramp inverts in dark mode, so --gray-100 cannot be both the page background and a card surface. The application's assets/css/tokens.css must declare these two names before the first application screen is written.

2.2 The semantic mapping

This table is normative. A screen that breaks it is wrong.

Semantic meaning mapped to a colour group
Meaning Colour group Example
Income / positive amount --success-* +1,200.00
Spending / negative amount --danger-* −42.80
Net positive --success-* +158.20
Net negative --danger-* −158.20
Net exactly zero Neutral --gray-* 0.00
Info / hint --info-* info
Destructive action --danger-500 button, --danger-100 background
Rule

A net of exactly zero is never green and never red. It is neutral. A zero total is not a success and not a failure.

Rule

An amount is always monospaced and tabular, so digits line up in a column. This is how a reader scans a ledger — not decoration. A total is larger than the rows above it and always carries its sign. Currency formatting follows the server's number_format() output: thousands separators, exactly two decimals, a leading symbol — €1,234.50.

5.10 Table

Example transaction ledger
Date ↓sorted descending Description Category Type Amount
2026-10-24 Weekly groceries Groceries Spending −42.80
2026-10-20 Salary Salary Income +1,200.00
2026-10-18 —No description Uncategorised Spending −18.00

Rule Tables use real <th scope="col">. Numeric columns are right-aligned and monospaced. The sort indicator is visible and announced to a screen reader.

Rule Every <td> in a data table carries a data-label attribute holding the column name in plain text. Below 640 px the table is re-laid-out as stacked cards: the <thead> is hidden visually, each row becomes a block, and the label is repeated next to the value. The attribute is the contract — a table without it loses its column names on a phone.

7. Handoff to the application implementer

Mapping from mockup artefact to application artefact
Mockup artefactApplication artefact
assets/tokens.css → :root assets/css/tokens.css — same names, same order
assets/base.css assets/css/base.css
assets/components.css assets/css/components.css
A screen NN-name.html assets/css/pages/<page>.css + the PHP page
  • The application loads the stylesheets in the order tokens.css → base.css → components.css → pages/<page>.css.
  • The application adds no colours of its own; a new colour is a new token in tokens.css.
  • The application escapes every dynamic value with e(); a mockup shows a literal string, the application shows an escaped one.
  • The mockup is the specification of appearance; the server remains the single source of truth for behaviour and data.
  • The mockup is not the security boundary — the server validates every form, owns every query and enforces every ownership filter.
